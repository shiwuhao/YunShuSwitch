# 编译与打包

从一台干净的 Mac 到可双击安装的 `dist/YunShuSwitch.dmg`，全程只需系统自带工具，**没有第三方依赖**。

---

## 一、准备

| 需要 | 检查命令 | 说明 |
|---|---|---|
| Xcode Command Line Tools | `xcode-select -p` | 没有就 `xcode-select --install`；提供 `swiftc` / `sips` / `iconutil` |
| macOS 13+（Apple Silicon） | `sw_vers` | 编译目标固定为 `arm64-apple-macos13.0` |
| Python 3（可选） | `python3 -V` | 仅打包 DMG 排版时用，缺了会跳过美化、不影响功能 |

> 不需要 Xcode 完整版、不需要 CocoaPods、不需要网络。

---

## 二、三条命令

```bash
git clone git@github.com:shiwuhao/YunShuSwitch.git
cd YunShuSwitch

./build.sh        # ① 编译 → build/YunshuSwitch.app
./install.sh      # ② 安装到 ~/Applications + 链接 ysctl + 启动（开发时用）
./make-dmg.sh     # ③ 打包 → dist/YunShuSwitch.dmg
```

只想发布、不想安装到本机？跳过第 ② 步直接 `./make-dmg.sh` 即可——它检测到源码比 App 新会自动先构建。

---

## 三、`build.sh` 做了什么

```bash
xcrun swiftc -O -target arm64-apple-macos13.0 \
  -framework Cocoa -framework ApplicationServices \
  -o build/YunshuSwitch.app/Contents/MacOS/YunshuSwitch ui/YunshuSwitch.swift
```

1. 清空 `build/YunshuSwitch.app`，建好 `Contents/MacOS` 与 `Contents/Resources`；
2. 把 `ui/YunshuSwitch.swift` 编译成单文件可执行程序；
3. 拷入 `ui/Info.plist` 并转成二进制 plist（`LSUIElement = true` → 纯菜单栏、无 Dock 图标）；
4. **把 `bin/ysctl`、`lib/yunshu-priv`、`lib/ui.applescript`、`ui/AppIcon.icns` 塞进 `Contents/Resources`**
   ——这样 App 是自包含的，只拖 App 也能完整使用；
5. 签名。

### 关于签名（很重要）

```bash
SIGN_ID="$(security find-identity -v -p codesigning | awk -F'"' '/Apple Development|Developer ID/{print $2; exit}')"
```

- **有开发证书** → 用它签。好处：TCC（辅助功能）授权绑定的是"签名身份 + bundle id"，
  重新编译后**授权依然有效**，不用再去系统设置里重新勾选。
- **没有证书** → 自动退回临时签名（`codesign --sign -`）。功能正常，但每次重编译都要重新授权一次。

自己编译给别人用，建议用 Developer ID Application 证书 + 公证（`notarytool`），否则对方首次打开要右键 →「打开」。
本项目发布的 DMG 用的是个人开发证书，所以你首次打开会看到「无法验证开发者」，右键打开一次即可。

> `--deep` 只是省事写法，正式分发建议对内部可执行文件逐个签名。

## 四、重新生成图标

图标不是图片素材，而是 `tools/Artwork.swift` 用 CoreGraphics **画**出来的（1024×1024 母版，遵守 macOS 图标的 80px 内缩 + 190px 圆角规范）：

```bash
xcrun swiftc -O tools/Artwork.swift -o build/artwork
./build/artwork icon build/AppIcon-1024.png     # 图标母版
./build/artwork dmg  build/dmg-bg.png           # 安装盘背景（1320×840）

# 母版 → 全尺寸 iconset → icns
rm -rf build/AppIcon.iconset && mkdir -p build/AppIcon.iconset
for sz in 16 32 128 256 512; do
  sips -z $sz $sz build/AppIcon-1024.png --out build/AppIcon.iconset/icon_${sz}x${sz}.png
  d=$((sz*2)); sips -z $d $d build/AppIcon-1024.png --out build/AppIcon.iconset/icon_${sz}x${sz}@2x.png
done
iconutil -c icns build/AppIcon.iconset -o ui/AppIcon.icns
```

改配色 / 形状 / 文案，直接改 `tools/Artwork.swift` 里的 `drawIcon` / `drawDMGBG`，重跑即可。
`make-dmg.sh` 会在 `ui/AppIcon.icns` 或 `build/dmg-bg.png` 缺失时自动补生成。

## 五、`make-dmg.sh` 做了什么

产物：`dist/YunShuSwitch.dmg`（卷名「云枢开关」，双击后是拖拽安装界面）。

盘内三件套：

| 条目 | 来源 |
|---|---|
| `云枢开关.app` | `build/YunshuSwitch.app`（改中文名） |
| `应用程序` | 指向 `/Applications` 的**软链**，拖进去就是安装 |
| `使用说明.txt` | `assets/使用说明.txt` |
| `.background/bg.png` | 安装盘背景（隐藏目录） |

流程：组装目录 → 建 40 MB 空白 **UDRW** 镜像 → `diskutil image attach --mountPoint build/dmg-mnt` →
拷入 → 写 `.DS_Store` 排版 → 卸载 → `hdiutil convert -format UDZO` 压缩 → 覆盖 `dist/YunShuSwitch.dmg`。

### macOS 上的三个坑（脚本里已固化，改脚本前务必读）

1. **`hdiutil create -srcfolder` 在新版 macOS 会直接压成只读 UDZO**，
   往挂载点写 `.DS_Store` 会报 `Read-only file system`。
   → 所以先 `hdiutil create -size 40m -fs HFS+ -volname 云枢开关` 建空白可写盘，再拷贝文件进去。
2. **`hdiutil attach -mountpoint` 已废弃且常被忽略**，卷会跑到 `/Volumes/<卷名>`；
   在 `/Volumes` 下写盘容易触发系统清理进程（`.BC.D_*` 临时文件）导致"操作不被允许"。
   → 改用 `diskutil image attach --mountPoint <工作区内路径> --mountOptions nobrowse`。
3. **`emulate -L zsh` 会复位 shell 选项**，`set -e` 必须写在它**之后**，否则中途失败仍会打印"完成"。

### 排版为什么不用 AppleScript

传统做法是 `osascript` 让 Finder 排版，但 `tell disk "云枢开关"` 需要「自动化」TCC 授权，
在脚本/CI 里调用只会静默失败（`-1728`），且必须真的弹出 Finder 窗口。

这里改成**直接写 `.DS_Store`**（`tools/mkdsstore.py`，依赖 `ds_store` + `mac_alias`）：

```bash
python3 -m pip install --user ds_store      # 只有排版需要
python3 tools/mkdsstore.py <挂载点> .background/bg.png
```

写入的键值：`bwsp`（窗口位置/尺寸）、`icvp`（图标大小 120、文字 12、背景图别名）、
`Iloc`（三个图标坐标）、`vSrn`（视图版本）。效果与 Finder 手动排完版完全一致，且零授权。

> 没有装 `ds_store` 时脚本只打印警告并跳过美化，DMG 照样能用，只是窗口位置为默认。

## 六、GitHub Actions（可选）

仓库自带 `.github/workflows/build.yml`：推送到 `main` 或手动触发，就会在 `macos-14` 上
`build.sh → make-dmg.sh`，并把 DMG 作为 artifact 上传。没有签名证书时会自动用临时签名，
适合验证"别人 clone 下来能不能编译"。

---

## 七、发布新版本清单

1. 改版本号：`bin/ysctl` 的 `VERSION`、`ui/Info.plist` 的 `CFBundleShortVersionString` / `CFBundleVersion`；
2. 更新 `CHANGELOG.md`；
3. `./build.sh && ./install.sh && ./make-dmg.sh`；
4. 验证：

   ```bash
   diskutil image attach dist/YunShuSwitch.dmg --mountPoint /tmp/vfy --mountOptions nobrowse
   ls /tmp/vfy/            # 云枢开关.app  应用程序  使用说明.txt  .background
   hdiutil detach /tmp/vfy
   ```

5. 提交代码与 `dist/YunShuSwitch.dmg`，打 tag（例如 `v1.3.0`）并推送。

## 八、编译常见报错

| 报错 | 原因 / 处理 |
|---|---|
| `xcrun: error: invalid active developer path` | 没装命令行工具：`xcode-select --install` |
| `error: unable to spawn process (Argument list too long)` | 旧版 SDK 问题，升级 macOS 或改用完整 Xcode |
| `codesign failed: errSecInternalComponent` | 钥匙串被锁，`security unlock-keychain` 后重试；或删掉证书改用临时签名 |
| `cannot be opened because the developer cannot be verified` | 用户侧右键 →「打开」；分发者应做公证 |
| `make-dmg.sh: device not configured` | 上一次挂载没卸干净：`hdiutil detach build/dmg-mnt -force` |
| `python3: No module named ds_store` | `python3 -m pip install --user ds_store`（或忽略，仅影响窗口排版） |
