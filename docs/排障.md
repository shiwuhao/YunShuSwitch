# 排障手册

按"症状 → 原因 → 处理"组织。先跑一次自检，大多数问题它会直接告诉你在哪一环：

```bash
ysctl doctor
```

---

## 0. 一分钟定位

```bash
ysctl doctor                                  # 路径、权限、辅助功能、隧道
tail -20 ~/Library/Logs/YunshuSwitch/ysctl.log   # 命令行每一步
tail -20 ~/Library/Logs/YunshuSwitch/app.log     # 菜单栏点击细节
```

`doctor` 正常时大概长这样：

```
macOS   : 27.0.1 (arm64)
云枢App : 存在
辅助功能：✅ 已授权（由菜单栏 App 执行点击）
免密提权：✅ 已安装（up/down 不再输密码）
隧道    : utun7 10.251.1.1 361
```

## 1. 每次连接/断开都弹「允许管理员访问由 zsh 启动的脚本吗？」

**原因**：`osascript ... with administrator privileges` 每次都要现场授权，**从不缓存**。说明免密助手这条链路没生效。

**判定**：

```bash
ls -l /usr/local/sbin/yunshu-priv /etc/sudoers.d/yunshu-switch
sudo -n /usr/local/sbin/yunshu-priv check; echo "rc=$?"
sudo -n /usr/local/sbin/yunshu-priv up;    echo "rc=$?"   # ← 关键：up/down 是否也放行
```

`check` 返回 0 但 `up` 要密码，就是 **sudoers 规则漏了 `up`/`down`**（1.1 及更早版本装出来的规则可能只有 `check`）。
这种情况下 `doctor` 会显示 ✅，很容易误判。

**处理**：

```bash
ysctl fix          # 等价于 setup --force：按 check/up/down 三条重写规则
```

或点菜单栏 →「一键修复（免密/授权）」。

**仍然弹框**？看 `tail -3 ~/Library/Logs/YunshuSwitch/ysctl.log` 里的 `PRIV ok=0 why=denied err=…`：

| `err=` | 含义 | 处理 |
|---|---|---|
| `a password is required` | 规则没匹配上（用户名/路径不一致） | `ysctl fix` 重写 |
| `operation not permitted` | 助手文件的属主或权限不对 | `sysctl` 见下：`sudo chown root:wheel /usr/local/sbin/yunshu-priv && sudo chmod 755 …` |
| `no such file` | 助手被删了 | `ysctl setup --force` |

> sudoers 文件若不是 `root:wheel`、权限不是 `0440`，sudo 会**静默忽略整份文件**：
> `sudo chown root:wheel /etc/sudoers.d/yunshu-switch && sudo chmod 440 /etc/sudoers.d/yunshu-switch`。

## 2. 点了「连接内网」，云枢起来了但没连上内网

**三个原因，按概率排序：**

1. **提权那步失败了，流程没走到"点连接"**。看 `ysctl.log` 是否有 `4/4 触发"连接"` 这行；没有就是卡在 `2/4 系统守护进程`。
2. **冷启动静默空操作**。云枢本地服务还没接上时，点「连接网络」返回成功但什么都不做，隧道永远不建立。
   1.2.0 起会自动补点、必要时**重启云枢再点一次**。看 `app.log`：

   ```
   axPress elements=6 panel=false
   verify round 1: 菜单仍显示「连接网络」，补点一次
   ```

3. **云枢弹了二次认证**（短信/扫码）。脚本等 45 秒会提示，完成后 `ysctl status` 复查。

还有一个**很容易中招的**：同时开着 Clash / Surge 之类的 TUN 模式，`ysctl up` 会直接打印
「内网已处于连接状态，无需操作」然后什么都不做。1.3.1 起已修复（判定要求云枢进程在跑，
并排除 fake-IP 的 `198.18/198.19` 网段）。如果你的版本仍这样，先 `ysctl --version` 确认 ≥1.3.1。

**手动确认界面状态**：

```bash
ysctl ui-dump       # 导出云枢界面元素，看按钮到底是「连接网络」还是别的文案
```

如果云枢升级后按钮文案变了，`ui-dump` 里会看到新文案，改 `YunshuSwitch.swift` 里 `axPressConnect` 的关键词即可。

## 3. `ysctl up` 返回 `NOBTN`

没在云枢界面匹配到连接按钮。按顺序排查：

| 日志 | 含义 | 处理 |
|---|---|---|
| `handle connect -> NOUI` | 云枢主程序没在跑 | `open -a /Applications/Yunshu.app` |
| `handle connect -> NOBTN` + `elements=0` | 云枢刚启动，可访问性树还是空的 | 等 3~5 秒再试；1.2.0+ 会自动重试 |
| `handle connect -> NOBTN` + `elements=6` | 树有元素但没匹配到按钮 | `ysctl ui-dump` 校对文案 |
| `handle connect -> NOAX` | App 没有辅助功能授权 | `ysctl ax` 后勾选「云枢开关」 |
| 完全没有 `handle` 行 | 请求没送到 App | `pgrep -fl Contents/MacOS/YunshuSwitch`，没跑就 `open -a` 拉起 |

## 4. `-25211 osascript 不允许辅助访问` / `-10004 权限违例`

这两个是 **1.1 之前**用 osascript 方案时的问题，1.2.0+ 已不再依赖：

- `-25211`：osascript 需要「辅助功能」，而授权对象是终端，换终端就失效 → 现在点击逻辑在 App 内；
- `-10004`：退出程序走 Apple Events 需要「自动化」授权 → 现在用 `SIGTERM`。

如果你的版本仍报这两个错，说明跑的是旧脚本：`ysctl --version` 确认，然后重新 `./install.sh`。

## 5. 菜单栏点了没反应 / 像卡住

| 原因 | 表现 | 处理 |
|---|---|---|
| 模态弹窗把菜单卡住 | 弹窗藏在别的窗口后面 | 1.1+ 弹窗已强制置顶，成功提示 6 秒自动消失 |
| 上一次操作卡在系统密码框 | `busy` 一直为真，菜单项全灰 | 1.2+ 有 150 秒看门狗，超时自动收尾；也可直接杀掉 App 重开 |
| App 没在运行 | 点图标无反应或图标消失 | `open -a ~/Applications/云枢开关.app` |
| 云枢可访问性树为空 | 日志 `elements=0` | 等几秒，程序会自动重试 |

## 6. 菜单栏没有云朵图标

菜单栏排满了（屏幕顶部空间不足）。按住 ⌘ 拖动图标调整顺序，或隐藏几个不常用的图标后重开 App。
App 在启动 2 秒后会自检，找不到图标位置会弹窗提示。

若图标偶发消失：`pgrep -fl Contents/MacOS/YunshuSwitch` 看进程在不在，在的话重启 App 即可（`killall YunshuSwitch` 后重新打开）。

---

## 7. 终端里 `command not found: ysctl`

App 首次启动时会把它链接到 `~/.local/bin/ysctl`。加 PATH：

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && exec zsh
```

或者 `ln -sf "$HOME/Applications/云枢开关.app/Contents/Resources/ysctl" ~/.local/bin/ysctl`。

---

## 8. 状态判断与实际不符

```bash
ysctl state      # connected / idle / off
```

- `connected`：找到 `utunN` 且至少有 5 条路由以它为网关；
- `idle`：云枢主程序在跑，但没隧道；
- `off`：主程序和守护进程都没了。

隧道刚建立/刚拆除的 1 秒内可能读到旧值（隧道探测有 0.6 秒缓存），属正常现象。

---

## 9. 卸载不干净

```bash
ysctl unsetup                                  # 移除免密助手
rm -rf ~/Library/Logs/YunshuSwitch             # 日志
rm -rf ~/Library/Application\ Support/YunshuSwitch  # 状态
rm -rf ~/Applications/云枢开关.app
rm -f ~/.local/bin/ysctl
```

云枢本身不受影响——`launchctl enable` 会恢复所有被禁用过的任务（`ysctl up` 也会）。

## 附：日志对照表

| 日志行 | 含义 |
|---|---|
| `perform start up ys=…` | 菜单点了，开始执行 |
| `handle connect -> OK` | App 真的在云枢界面点中了「连接网络」 |
| `handle connect -> NOBTN` | 没匹配到按钮文案（用 `ysctl ui-dump` 校对） |
| `handle connect -> NOUI` | 云枢主程序没在跑 |
| `verify round 1: 菜单仍显示「连接网络」，补点一次` | 第一次点击被静默忽略，已自动补点 |
| `perform done rc=0 out=…` | 结束，rc 与最后几行输出 |
| `PRIV ok=1 why=` | 走的是免密助手 |
| `PRIV ok=0 why=denied err=…` | 免密不可用，看 err 决定处理方式 |
| `ADMIN fallback` | 回退到系统密码框 |
